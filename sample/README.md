# Sample corpus

Test documents for eyeballing the renderer. Nothing here ships — [`.vscodeignore`](../.vscodeignore) keeps `sample/**` out of the `.vsix`.

Open any of these in the Extension Development Host (<kbd>F5</kbd>) with **Sheaf (WYSIWYG)**. Every document is fictional; there are no real people, companies, or endpoints in the corpus.

## Layout

| Directory | What it is for |
| :--- | :--- |
| [`sample/`](.) | One file per construct family. The fastest way to check a specific feature. |
| [`sample/dialect/`](dialect/) | Every construct, split by dialect: plain CommonMark, what GitHub adds on top, what Sheaf adds on top of that. The three together are the fastest way to eyeball a change, and the place to decide whether a difference against another renderer is a bug or a dialect. |
| [`sample/docs/`](docs/) | Realistic documents of the kinds people actually keep in a repo. Read these to judge whether the editor feels right, not just whether it parses. |
| [`sample/edge/`](edge/) | Ambiguous, hostile, and non-ASCII input. Where rendering bugs live. |
| [`sample/stress/`](stress/) | Generated bulk — long documents, big tables, thousands of rows. Performance, not correctness. |
| [`sample/edge/bytes/`](edge/bytes/) | Generated byte-level cases: empty files, CRLF, BOM, invalid UTF-8, one 200 KB line. |
| [`sample/wild/`](wild/) | Real Markdown written by other people, downloaded on demand. Not committed. |
| [`sample/wren-4/`](wren-4/) | A themed, fictional repository full of tables and charts. Made for demos and screenshots. |
| [`sample/assets/`](assets/) | Generated placeholder images the documents link to. |

## Wren-4, a themed corpus (generated)

[`wren-4/`](wren-4/README.md) is the repository of a fictional deep-space navigation beacon: a station log, an incident report, space weather, an eclipse and power schedule, ship traffic, radio signal detections, stores, a runbook and a noodle recipe. Everything comes from one dataset, so a figure in a table matches the same figure in a chart and in the prose. Regenerate it with `npm run gen:wren4`.

There is also a story hidden in it, with several ways in. Each clue sits in a different layer of a document: table data, a hex dump, raw source, a collapsed section, a file nothing links to, and the fine detail of an image. Finding them all means using every way the editor shows or hides content, which makes it a decent tour of the editor as well. The walkthrough, with spoilers, is at the top of [`scripts/gen-wren4.mjs`](../scripts/gen-wren4.mjs).

It is the corpus for judging whether Sheaf feels good to use and for screenshots, and it covers every way a chart turns up in Markdown:

| Form | Where | Renders in Sheaf today |
| :--- | :--- | :--- |
| SVG chart images: line, stacked bar, grouped bar, scatter, pie, heat map | [`wren-4/charts/`](wren-4/charts/) | Yes, as images |
| Mermaid `xychart-beta`, `pie`, `gantt`, `timeline`, `quadrantChart`, `sankey-beta`, `flowchart`, `stateDiagram-v2` | Most documents | No, shown as code |
| Vega-Lite and note-app `chart` blocks | [`space-weather.md`](wren-4/space-weather.md) | No, shown as code |
| Charts drawn in text with block characters, and inline sparklines | Log, space weather, signals | Yes, as text |
| `csv` blocks of 48 to 61 rows | Space weather, eclipses | Yes, as grids |
| Pipe tables from 2 to 14 columns and up to 31 rows, with totals, bold and links in cells | Every document | Yes |
| Block and inline maths, a link-budget table, C and Python | [`beacon.md`](wren-4/beacon.md) | Code yes, maths no |

## Real-world documents (downloaded)

Everything above is written by us, so it only contains what we thought to test. `sample/wild/` fills that gap with Markdown other people wrote for their own reasons: specs, API references, changelogs, site docs full of template tags, a 1,900-row table README, a novel.

```sh
npm run fetch:wild
```

That downloads 20 files, about 3.3 MB, into `sample/wild/files/`, which git ignores. [`wild/manifest.json`](wild/manifest.json) pins each GitHub source to a commit and every file to a SHA-256, and records its licence and what it exercises. Sizes run from 800 bytes to 840 KB, split into `short`, `medium` and `long`.

The files are never committed. Each one is published under an open licence (CC0, public domain, MIT, Apache-2.0, CC BY, CC BY-SA or GPL), so downloading and reading them for testing is permitted. Committing them would mean carrying each licence's attribution and share-alike terms inside an MIT repository, and a manifest avoids that. To add a source, pick one whose licence is stated in its repository, pin it to a commit, and add an entry with its checksum.

## Adding to the corpus

- Keep committed files fictional. No real names, addresses, tokens, or internal URLs. Real documents belong in the `wild` manifest.
- Put hand-written files in `docs/` or `edge/` and list them above. Bulk belongs in the generator, not in a pasted file.
- Prefer content that is plausible over content that is filler. A document you would not mind reading is a better test of whether the editor is pleasant to use.
